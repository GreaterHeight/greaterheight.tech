What We Test

Six types of testing, applied where each does the most good

Different parts of a software system fail in different ways. Each testing type is a lens for a specific category of failure — applying all six to every project is wasteful; applying the right ones in the right sequence is effective.

🔍

Functional Testing

Verifies that every feature behaves as specified. The baseline for every engagement — nothing moves forward until it passes.

🔄

Regression Testing

Confirms that changes to the codebase have not broken existing functionality. Automated suites make regression fast and consistent.

📈

Performance Testing

Measures response times, throughput, and resource consumption under realistic and peak load. Surfaces the bottlenecks before users hit them.

🔒

Security Testing

Identifies vulnerabilities in authentication, authorisation, data handling, and third-party integrations before attackers find them.

♿

Accessibility Testing

Verifies WCAG 2.1 AA compliance for keyboard navigation, screen reader compatibility, colour contrast, and focus management.

📲

Mobile & Cross-Browser

Tests across iOS, Android, Chrome, Safari, Firefox, and Edge. Surfaces layout and behaviour differences before they reach real devices.

Bug Prioritisation

Not all bugs are equal. We triage by impact and likelihood.

Every defect we find is classified on two axes: the impact it has if it occurs, and the likelihood that a user will encounter it. This tells the development team what to fix first and what can wait for the next sprint without compromising the release.

1
Critical: Blocks core functionality or exposes data. Release is blocked until resolved.
2
High: Significant user impact on a likely path. Must be fixed before launch.
3
Medium: Noticeable but not blocking. Scheduled for the next sprint.
4
Low: Cosmetic or edge-case. Logged in backlog with no urgency.

Before we start

We provide functional testing, regression testing, automated end-to-end testing, performance and load testing, security and penetration testing, accessibility testing, API testing, and mobile app testing. The mix varies by project: a startup preparing for launch typically needs functional and regression coverage first; a high-traffic platform under scaling pressure needs load and performance profiling; a consumer application seeking WCAG compliance needs an accessibility audit. We assess what a project needs and build a test strategy accordingly rather than applying a fixed suite to every engagement.

We build automated test suites that run on every commit or pull request as part of a CI/CD pipeline. The automation covers the most stable, highest-value paths first — user journeys that must work on every release — and grows incrementally rather than trying to automate everything at once. We use Playwright, Cypress, Selenium, Appium, Jest, Pytest, and k6 depending on the technology stack. The test suite becomes a permanent asset of the codebase, not a one-time deliverable that becomes unmaintained after the engagement ends.

From the audit we produce a prioritised testing plan. We then build out the missing coverage incrementally. For projects with no testing at all, we start with smoke and regression tests for the most critical flows, then expand coverage into edge cases and negative scenarios over subsequent sprints.

Quality Assurance is process-oriented: it sets up the conditions, workflows, and standards that prevent defects from being introduced in the first place — test planning, review processes, standards, checklists. Quality Control is product-oriented: it checks whether the product meets the required standards — running tests, finding defects, reporting them. In practice the two work together. Our QA service covers both: we design the testing process and standards (QA), and we execute the testing that finds and reports defects (QC).

QA engagements are structured in two ways. A project-based engagement covers a defined scope of work — a release, a migration, an audit — with a fixed deliverable and timeframe. A retainer-based engagement provides ongoing QA support across a team's development cycle, reviewing releases and maintaining the test suite. Pricing depends on the scope and the mix of manual versus automated testing required. We quote after a brief discovery call where we assess the application, the stack, the team's existing process, and the coverage gaps to be addressed.
