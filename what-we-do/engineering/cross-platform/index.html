The Architecture

One shared codebase. Each platform feels native.

The engineering challenge in cross-platform development is not writing one codebase — any framework can do that. The challenge is ensuring each platform receives an experience that feels as though it was built specifically for it. Navigation patterns, interaction models, and platform conventions all differ between iOS and Android. We build the shared layer right, then write the platform-specific layer properly rather than forcing one pattern everywhere.

80-95%

Shared business logic

API calls, data models, state management, validation, and navigation all live in a shared layer — written once, tested once, deployed everywhere.

5-20%

Platform-specific layer

Device APIs, native UI conventions, platform-specific performance optimisations, and hardware integrations. This layer is where native feel is earned.

Choosing the Right Approach

When cross-platform is the right choice — and when it is not

We will tell you honestly whether cross-platform is the right approach for your project. For most business applications, it is. For some, native is genuinely the better answer. Here is the distinction.

Cross-platform is the right fit when

Your app is primarily UI-driven, data-driven, or business-logic-driven — the category that covers most commercial software

You need to reach both iOS and Android users quickly, without double the budget and double the team

Your team will maintain and extend the app after launch and needs a single codebase rather than two separate ones to manage

You also need a web or desktop version and want to share as much logic as possible with the mobile build

Performance requirements are standard to good — which covers social apps, fintech, logistics, enterprise tools, and marketplaces

Consider native when

The app relies heavily on cutting-edge hardware: advanced AR/VR, complex camera processing, or real-time graphics rendering at high frame rates

You need to push device hardware performance to its absolute limits — competitive gaming, complex simulations, real-time video processing

You are building only for one platform and have no plan to expand — the shared codebase advantage does not apply if there is nothing to share it with

The app requires very deep integration with platform-specific system APIs that cross-platform frameworks do not yet expose

If you are not sure which category your project falls into, that is exactly what a scoping conversation is for. We will give you a recommendation with clear reasoning — not an answer shaped by what we prefer to build.

Technology Choices

The frameworks we build with, and why

Framework choice is a technical decision with long-term consequences. We use the framework that best fits your project's requirements and your team's context — not the one we happen to prefer.

React Native

React Native

Facebook's open-source framework for building mobile apps using JavaScript and React. The largest ecosystem in cross-platform mobile development with the widest library support and the most active community. When your web team already builds in React, React Native reduces the learning curve significantly and allows partial talent sharing between mobile and web builds.

Largest third-party library ecosystem in mobile cross-platform
Hot reload for fast iteration during development
Strong enterprise adoption with proven production stability
Can integrate native modules written in Swift or Kotlin
Best fit for

Teams with existing JavaScript expertise; apps needing deep third-party integrations; projects where talent flexibility matters

Flutter

Flutter

Google's UI toolkit for building natively compiled applications from a single codebase across mobile, web, and desktop. Flutter renders its own UI components rather than wrapping native ones, which delivers exceptional visual consistency across platforms and excellent performance. The highest code-sharing ratio of any mature cross-platform framework.

80 to 95 percent code sharing across iOS, Android, web, and desktop
Pixel-perfect UI consistency across all platforms
60fps rendering performance without native bridges
Single framework covers mobile, web, and desktop targets
Best fit for

New projects starting fresh; apps requiring pixel-precise design across platforms; maximum code reuse including web and desktop

Progressive Web Apps

Progressive Web Apps (PWA)

Web applications built to behave like native apps on mobile and desktop — installable from the browser, capable of offline operation, and accessible with a URL rather than an app store listing. PWAs remove the friction of app store submission and work on any device with a modern browser. The right choice when distribution speed and cross-device reach matter more than deep hardware access.

No app store listing required — distribute via URL
Works offline with service worker caching
Instant updates without user-initiated app store updates
Lower distribution barrier, especially for enterprise tools
Best fit for

Content-driven apps, enterprise internal tools, apps where fast distribution and offline capability matter more than hardware access

.NET MAUI

.NET MAUI / Xamarin

Microsoft's cross-platform framework for building native apps in C#. MAUI is the successor to Xamarin and targets iOS, Android, macOS, and Windows from a single codebase. The natural choice for organisations already operating a .NET-based technology stack, as it allows the mobile team to work in the same language and share code with existing backend services.

C# and .NET throughout — consistent with enterprise Microsoft stacks
Share backend logic and models with existing .NET services
Strong enterprise support and long-term Microsoft commitment
Native API access on all target platforms
Best fit for

Organisations with existing .NET or Azure infrastructure; enterprise mobile tools where backend code sharing matters

Why GreaterHeight

We build for the users your app needs to reach

Both platforms, without compromise

We do not treat one platform as the main version and the other as the port. iOS and Android receive equal design attention, equal testing time, and equal performance benchmarking. Users on either platform get a first-class experience.

Framework-agnostic recommendations

We do not have a preferred framework that we push regardless of your context. We recommend based on your existing tech stack, your team's skills, your performance requirements, and your roadmap. The recommendation comes with reasoning, not marketing.
